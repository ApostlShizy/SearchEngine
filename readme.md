# Алгоритм поиского движка

**Проект собран с помощью CMake в Qt**

Для этого приложения конфигурационные данные будут храниться в файле с
 названием "config.json", пользовательские запросы — в файле "requests.json", а ответы —
 в "answers.json".
 Все три файла по умолчанию находятся в директории с проектом, там же приложение будет искать их по умолчанию (пути записи/чтения можно поменять в методах классов).

<br>


### Файл конфигурации "config.json".
    Без него запуск приложения невозможен. Он содержит название поискового движка,
    его версию, время обновления базы (с какой периодичностью необходимо делать
    переиндексирование базы, заново подгружать файлы и обсчитывать их поисковый
    рейтинг), максимальное количество вариантов в ответе (если не указано, то значение
    выбирается равным пяти).

Пример описания файла config.json:

```json
 { 
    "config": {
        "name": "SearchEngine",
        "version": "0.1",
        "max_responses": 5
    },
    "files": [
        "../resources/file001.txt",
        "../resources/file002.txt",
        "../resources/file003.txt",
        "../resources/file004.txt",
        …
    ]
 }
```

 ### Подробнее разберём каждое поле файла config.json:
 - config — общая информация, без которой приложение не запускается. Если это
 поле отсутствует, то при старте программа выбросит исключение "config file is empty". Если отсутствует сам
 файл config.json, то "config
 file is missing".

 - name — поле с названием поискового движка. Оно может быть любым.

 - version — поле с номером версии поискового движка.

- max_responses — поле, определяющее максимальное количество ответов на
 один запрос.

- files содержит пути к файлам, по которым необходимо осуществлять поиск.
 Внутри списка files лежат пути к файлам.

- <путь к файлу>(“../resorces/file001.txt”) — это путь к файлу. Впоследствии по его
 содержимому совершается поиск (так же можно передать уже готовый текст в класс [InvertedIndex](#InvertedIndex) для обновления или создания базы данных на основе этого текста). Если по этому пути файл не
 существует, то на экран выводится соответствующая ошибка, но выполнение
 программы не прекращается. При этом каждый документ содержит не более
 1000 слов с максимальной длиной каждого в 100 символов. Слова
 состоят из строчных латинских букв и разделены одним или несколькими
 пробелами.

<br>


### Файл с запросами "requests.json".
 Он содержит запросы, которые необходимо обработать поисковому движку (так же можно передать уже готовые запросы в класс [InvertedIndex](#InvertedIndex) не прибегая к чтению файла).

 Пример описания файла "requests.json":
 ```json
 {
    "requests": [
        "some words..",
        "some words..",
        "some words..",
        "some words..",
        …
    ]
 }
 ```

<br>


 ### Файл с ответами на запросы "answers.json".

 В него записываются результаты работы поискового движка. Если файл уже существует, и по данному пути ведётся новая запись весь ответ обновляется.

 Пример описания файла answers.json:

 ``` json
 {
    "answers": {        
        "request001": {
            "result": "true",
            "relevance": {
                [
                    {
                        "doc_id": 0,
                        "rank": 1.0
                    },
                    {
                        "doc_id": 1,
                        "rank": 0.3333333432674408
                    },
                    {
                        "doc_id": 2,
                        "rank": 0.2222222238779068
                    }
                ]
            }
        },
        "request002": {
            "result": "true",
              "relevance": [
                {
                    "doc_id": 5,
                    "rank": 1.0
                },
                {
                    "doc_id": 3,
                    "rank": 1.0
                }
            ]
        },
        "request003": {
            "result": "false"
        }
    }
 }

 ```
 Рассмотрим каждого поле файла "answers.json":
 - answers — базовое поле в этом файле, которое содержит ответы на запросы.
 - request001 … 003 —идентификатор запроса, по которому сформирован ответ.
 Идентификатор запроса формируется автоматически по порядку, в котором
 находятся запросы в поле requests файла "requests.json". 
 
 Например:
 ``` json
 {
    "requests": [
        "some words..", для данной строки id запроса будет равен “request001”
        "some words..", для данной строки id запроса будет равен “request002”
        "some words..", для данной строки id запроса будет равен “request003”
        "some words..", для данной строки id запроса будет равен “request004”
        …
    ]
 }
 ```
 - result – результат поиска запроса. Если он принимает значение "true", значит по
 данному запросу найден хотя бы один документ. Если результат имеет значение
 "false", значит ни одного документа не найдено. Тогда других полей в ответе на
 этот запрос нет.

 - relevance релевантность ответа. Далее идут соответствия рейтинга ответа и названия id документа, в котором осуществлялся поиск.

 - <Идентификатор документа>("docid") — идентификатор документа, в котором
 найден ответ на запрос. Он формируется автоматически при индексации всех
 документов исходя из порядка, в котором документы расположены в поле "files" в
 файле "config.json". Например, если в поле config.json поле files содержит:

 ``` json
 {
    "files": [
        "../resources/file001.txt", для данного файла docid будет равен 0
        "../resources/file002.txt", для данного файла docid будет равен 1
        "../resources/file003.txt", для данного файла docid будет равен 2
        "../resources/file004.txt", для данного файла docid будет равен 3
        …
    ]
 }
 ```
 ● <ранг ответа>(“rank”) — ранг или поисковый рейтинг. Это число показывает,
 насколько документ подходит для заданного запроса. В ответе id документов
 располагаются в порядке уменьшения поискового рейтинга.

## ConverterJSON

Данный класс работает с файлами json, ведёт их запись и чтение использя библиотеку __nlohmann_json__.

В классе придсутсвует поле:

```C++
size_t maxResponse = 1000; /* Максимальное количество ответов на запрос */
```

В классе присудствуют такие методы как:

### 1. getMaxResponse
``` C++
size_t getMaxResponse()
```
    Получить максимальное колиество ответов на запрос. По умолчанию 1000. 


### 2. getConfig

```C++
int getConfig(std::vector<std::string>& filePath,std::string configPath = "config.json")
```
    Метод принимает вектор строк в который вписывает пути к документам. Вписывает в поле "maxRespone" максимальное количество ответов на один запрос Возврщает int с кодом выполнения "configPath" путь к файлу конфигурации.

### 3. getRequests

```C++
std::map<size_t, std::vector<std::string>> getRequests(std::string requestsPath = "requests.json")
```

    Чтение и составление списков запросов, метод берёт запросы из файла "requests.json". Вписывает их в std::map где size_t индекс запроса, а std::vector<std::string> вектор запроса разбитый на отдельные слова. Слова в запросе должна быть записаны на латинице (пока поддерживает только анлгийский алфавит) и между каждым словом должен быть пробел, чтобы метод мог корректно определять отдельные слова.


### 4. putAnswers

``` C++
void putAnswers(std::vector<std::vector<RelativeIndex>>& answerValue,std::string answerPath = "answers.json")
```
    Данный метод берёт готовый список "answerValue" и помещает его в файл "answers.json".

Структура "RelativeIndex" описана в классе [SearchServer](#SearchServer)

## InvertedIndex

Данный класс принимает текстовые блоки и формирует из них
инвертированный индекс. В классе присудствуют методы с многопоточностью. Так же в InvertedIndex.h описана структура __Entry__:
``` C++
struct Entry {
    size_t doc_id, count;

    // Данный оператор необходим для проведения тестовых сценариев
    bool operator == (const Entry& other) const {
    return (doc_id == other.doc_id && count == other.count);
    }
};
```

Данная структура ведёт учёт документов (doc_id) и количество включений слов из запросов в тех (count).

В классе придсуствуют такие поля:

```C++
std::mutex freqDictionaryMutex; /* Мьютекс для метода определения количества вхождений*/

std::mutex updateDocsMutex; /* Мьютекс для обновления библиотеки документов */

std::vector<std::string> docs; /* список содержимого документов */

std::map<std::string, std::vector<Entry>> freqDictionary; /* частотный словарь */
```

В классе присудствуют такие методы как:

### 1. setfreqDictionary

```C++
void setfreqDictionary(const std::string & word, std::vector<Entry> & wordCount)
```
    Данный метод принимает слово (word) и его вектор стурктур (wordCount) для обновления частотного словаря.

### 2. updateDocumentBase
```C++
void updateDocumentBase(const std::vector<std::string>& inputDocs)
```
    Данный метод принимает текст из документов (inputDocs), после передаёт его в отдельный поток методу InvertedIndex::updateDocumentBaseThread для записи списка документов в базу данных класса (docs).

### 3. getDictionary
```C++
const std::map<std::string, std::vector<Entry>> & getDictionary()
```
    Возвращает константную ссылку на частотный словарь.

### 4. getWordCount
```C++
std::vector<Entry> getWordCount(const std::string& word)
```
    Метод определяет количество вхождений слова в загруженной базе данных. Принимает слово (word) и передаёт его в отдельный поток методу InvertedIndex::getWordCountThread. Каждый из которых проходится по своему документу из базы данных.

## SearchServer

Данный класс составляет списки валидности анализируя записанную базу документов и составленную списки валидности для каждого из запросов. SearchServer.h описана структура __RelativeIndex__: 
```C++
struct RelativeIndex{
    size_t doc_id;
    float rank;
    // Данный оператор необходим для проведения тестовых сценариев
    bool operator ==(const RelativeIndex& other) const {
    return (doc_id == other.doc_id && rank == other.rank);
    }
};
```

### Конструктор класса 
```C++
SearchServer(InvertedIndex& idx) : invIndex(idx){ };
```
В конструктор класса передаётся ссылка на класс [InvertedIndex](#InvertedIndex), чтобы SearchServer мог узнать частоту слов встречаемых в запросе.

В классе придсуствуют такие поля:
```C++
    InvertedIndex & invIndex; /* Ссылка на класс InvertedIndex */
```

В классе присудствуют метод:

### search

```C++
std::vector<std::vector<RelativeIndex>> search(const std::map<size_t, std::vector<std::string>>& request,size_t maxResponse = 1000)
```
    Метод обработки поисковых запросов. "request" поисковые запросы. maxResponses количество ответов на запрос. Для работы метода в объекте класса InvertedIndex по ссылке должны быть составлены: как база данных документов так и инвертированный индекс.
